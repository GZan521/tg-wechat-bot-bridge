# tg_wechat_bot_bridge

把你的 AI 助手（Muse）接进 **Telegram** 或 **微信 ClawBot** 的一份智能体技能（Skill）。

把这份 skill 交给一个智能体，它就会一步一步引导你完成对接：每一步都说清「你做什么、做完怎么验」，验过才走下一步。对接完成后，你可以在 Telegram 或微信里直接和自己的助手聊天，文字、图片、视频双向收发，就像它住在你的聊天软件里。

## 它能做什么

- **双通道，二选一或都接**：Telegram 走 Bot API，微信走腾讯官方 iLink / ClawBot 协议，两种通道共用同一套桥的设计骨架。
- **多媒体双向**：文字、图片、视频、文件在两个通道都能收能发；Telegram 额外支持语音双向（你发语音，它转写后用语音回你），微信语音只能收不能发（通道会静默丢弃 bot 发出的语音，这是协议现状，skill 里写明了替代办法）。
- **无常驻进程**：靠轮询 hook + 持久队列工作，机器重启不丢消息；发送带幂等账本，同一条消息不会重复发；看门狗只在状态变化时才提醒你。
- **安全边界写死在流程里**：token / 登录会话只存本地、绝不进聊天和仓库；微信新联系人上白名单只能由你在主对话里批准，陌生人没法在微信里把自己聊进白名单。

## 两个通道的能力对照

| 能力 | Telegram | 微信 ClawBot |
| --- | --- | --- |
| 文字 | 双向 | 双向 |
| 图片 | 双向 | 双向 |
| 视频 | 双向 | 双向 |
| 文件 | 双向（下载上限 20 MB） | 双向 |
| 语音 | 双向（本地转写 + 语音合成回复） | 仅接收（自带转写），发送会被通道丢弃 |
| 你要做的事 | 找 @BotFather 建 bot、关掉群隐私 | 扫码登录、10 分钟内发第一条消息绑定主人 |
| 验证状态 | ✅ 已在作者的真实环境跑通并日常使用 | 📖 经验蒸馏自开源项目，尚未在作者环境部署，首次部署按受监督试运行对待 |

## 工作原理

整套桥拆成四个可独立更换的部件，换任何一个都要四个一起对齐（这是实测踩过的坑）：

1. **协议客户端脚本**：只负责和平台说话。收消息分两段：先拉取入队，确认落盘后才推进游标，保证至少送达一次、不静默丢消息。
2. **轮询 hook 脚本**：定时被唤醒做一次长轮询，带单实例锁、心跳文件和唤醒节流（新消息立即唤醒，积压提醒至少间隔 2 分钟）。
3. **worker 提示词**：写在 hook 定义里的应答规矩——认领队列、打开附件再回复、判断该回谁、防刷屏上限（连续回复 5 条且无人说话就停）、发送幂等键。它是一等组件，不是附属品。
4. **看门狗**：定时查心跳，只在「停摆」和「恢复」两个状态变化点发消息，平时安静。

```

    ├── worker-prompt-template.md    # worker 提示词模板（占位符版，填好再注册 hook）

```

## 怎么用

**给 Muse 类智能体用（推荐）**：把整个仓库文件夹放进智能体的工作区技能目录（例如 Muse 的 `~/workspace/custom-skills/tg_wechat_bot_bridge/`），或把仓库压缩包发给它，然后对它说一句「用 tg_wechat_bot_bridge 帮我接 Telegram」或「……接微信 ClawBot」，它就会按 SKILL.md 开始引导你。

**给其他智能体用**：把 `SKILL.md` 全文作为指令交给它，并让它能读到 `references/` 里的文件，效果相同。

对接过程中，所有需要你本人做的事（建 bot、扫码、发绑定消息）智能体都会停下来等你，并给出验证方法；涉及 token、登录会话这类敏感物，它只会让你在本机保存，绝不要求你发到聊天里。

## 前置条件

- 一个能跑智能体 + 定时 hook 的环境（本 skill 按 Muse 的运行环境编写，其他环境需自行适配 hook 与看门狗部分）。
- Telegram 通道：一个 Telegram 账号，用来向 @BotFather 申请 bot。
- 微信通道：一个微信账号，用来扫码登录 ClawBot；另外需要克隆上游项目 [gfydfhcf/wechat-ilink-muse-bridge](https://github.com/gfydfhcf/wechat-ilink-muse-bridge) 并按其根目录 AGENTS.md 的部署契约执行，本仓库的 `references/wechat-ilink-notes.md` 是配套的协议笔记。
- 语音闭环（可选，仅 Telegram）：本地语音转写（如 faster-whisper）与一个你认可的语音合成音色。

## 安全须知

- bot token、微信 `session.json` 等同于密码：只存本地，权限收紧，不要提交进任何 git 仓库。本仓库附带的 `.gitignore` 已预置这些文件名，但换环境时请再核对一遍。
- Telegram 群里 bot 看不到其他 bot 的消息（Bot API 的硬限制），不要指望两个 bot 在群里互相聊天；真要中继需要一个真人账号做中间人，那是另一套东西。
- 微信通道里 bot 只能收到发给 bot 本人的消息，读不到你自己的聊天、通讯录和朋友圈，这是协议边界，不是配置问题。
